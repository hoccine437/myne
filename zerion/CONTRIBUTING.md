# Contributing

1. Read `constitution/constitution.txt`, `SECURITY.md`, and `BUILD.md`.
2. Do not edit protected core files through the evolution workflow.
3. Preserve public APIs and terminal-first behavior.
4. Keep modules focused and under 300 lines where practical.
5. Add regression tests for every behavior change.
6. Run the complete suite in `QUICK_RUN.md` before submitting changes.
7. Never commit `.env`, API keys, generated voice models, `.zerion/` runtime state, or local provider health databases.
8. Use the staged Evolution workflow for non-protected self-evolution changes; obtain approval before deployment.
